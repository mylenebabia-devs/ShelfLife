# ShelfLife 1.9 — Measurement and batch forms

Product measurement now has an optional numeric value and a selectable unit: kg, g, mg, L, ml, oz, lb, pcs. These appear in Add and Edit and persist to nullable measurementValue/measurementUnit SQLite columns on product identities and batch snapshots. Measurement is distinct from stock-count unit (e.g. one 155g can counted in pieces or cartons).

Detection uses explicit barcode catalog pack size or the entered product name. It recognizes numbers and supported unit spellings, including decimals. Unit-only information fills only the unit. Missing information stays blank; category alone never implies weight. Multipack/ambiguous sizes do not supply an assumed amount. Manual changes take precedence over later suggestions. Existing free-text pack size is retained for compatibility and is synchronized when staff corrects measurement. Existing records are preserved; explicit old pack sizes are detected when their form opens.

Batch Information now includes Quantity received and Quantity remaining, supplier lot, received date, printed expiry/best-before date and storage location. Both counts are required; remaining must be between zero and received. Receipt creates stock-in and, when needed, a quantity-correction entry so recorded movements reflect initial remaining stock. Edits update the same batch; changed counts record corrections. Product metadata applies to all its batches. CSV inventory export includes received quantity and measurement fields.

New SKU example: SAR-MEG-155-TS. The numeric pack size is used when available. Different measurement units may initially produce the same abbreviated base; the existing transaction/UNIQUE constraint allocates a distinguishing suffix for different products. Incomplete details use consistent GEN/STD fallback codes. Existing SKU values are never regenerated or changed, including older SKUs with size units in them. Add stock retains the same product identity/SKU and creates another batch ID.

Version 1.9-measurements, version code 11, database version 9. Update with the same signing key; do not clear app data. Migration adds measurement columns without resetting records.
